# LLM 프롬프트 설계

> Accio Recipe의 핵심 AI 기능인 "비정형 레시피 콘텐츠 → 구조화 JSON 변환"을 위한 시스템 프롬프트 설계 문서입니다.

---

## 1. 설계 목표

레시피 영상(YouTube)이나 블로그 글의 비정형 콘텐츠를 LLM에게 입력하여, **조리 UI에서 그대로 렌더링 가능한 구조화 JSON 데이터**로 변환하는 것이 목표였습니다.

단순히 "레시피 정보를 추출해줘"라는 자연어 지시만으로는 다음과 같은 문제가 발생할 것을 예상했습니다.

- LLM이 임의로 정보를 생성(hallucination)하거나 누락
- 응답 형식이 매번 달라서 UI 렌더링 불안정
- 조리 단계와 재료 정보가 분리되어 사용자 흐름이 끊김

따라서 프롬프트를 **"페르소나 + 핵심 규칙 + Structured Output(JSON 스키마)"** 3가지 축으로 설계했습니다.

---

## 2. 페르소나 설정

```text
너는 최고의 요리 전문가이자 레시피 구조화 AI야.
주어진 동영상이나 텍스트를 보고 오직 '요리 레시피'와 관련된 필수 정보
(제목, 난이도, 몇인분, 재료, 스텝)만 정확하게 추출해야 해.
```

LLM에게 두 가지 역할을 동시에 부여했습니다.

- **요리 전문가**: 레시피 도메인에 대한 판단 기준 확보
- **구조화 AI**: 단순 자연어 응답이 아닌 데이터 가공자 역할

또한 추출 대상을 **'요리 레시피와 관련된 필수 정보'로 한정**함으로써, 영상에 등장하는 부수적인 정보(셰프 인사말, 광고, 음악 추천 등)가 응답에 섞이는 것을 방지했습니다.

---

## 3. 핵심 규칙 3가지

프롬프트의 가장 중요한 부분으로, 추출 결과의 품질을 결정하는 영역입니다.

### 규칙 1. 조리 흐름 중심 구조화 — "지시문 안에 계량 수치 금지, 단 시간·온도는 보존"

```
조리 순서(instruction) 텍스트 안에 절대 구체적인 재료 무게/부피 계량 수치
(예: 370g, 200ml, 1큰술 등의 숫자+단위)를 적지 마라.

- BAD 예시: "크림치즈 370g을 볼에 넣고 부드럽게 풀어준다."
- GOOD 예시: "계량한 크림치즈를 볼에 넣고 부드럽게 풀어준다."

하지만 조리에 필요한 "시간(분, 시간, 초)"이나 "온도(도)"와 관련된 안내
(예: "220도로 22분동안 구워주세요", "15분간 불려주세요")는 절대로 삭제하지
말고 원본 텍스트 그대로 보존해라.
```

**의도**: 조리 단계의 지시문은 "지금 무엇을 해야 하는지"에 집중되어야 합니다. 재료의 양은 별도 필드(`step_ingredients`)에서 관리하므로 지시문 안에 중복 표기되면 정보가 불필요하게 반복됩니다.

반면 **시간/온도 정보는 조리 흐름의 핵심 변수**이므로 별도 필드로 분리하지 않고 지시문 안에 그대로 보존하도록 명시했습니다. "계량 수치 금지"라는 규칙을 단순화하면 시간·온도까지 같이 사라질 수 있어서, 두 가지를 명확히 구분하는 안전장치를 넣었습니다.

### 규칙 2. 단계별 재료 연결 — `step_ingredients` 매핑

```
각 조리 단계(step)마다 해당 단계에서 실제로 투입되거나 사용되는 재료들의
상세 정보(이름, 양, 단위)를 객체 배열 형식으로 명시해라.

이름은 반드시 전체 ingredients 목록에 존재하는 name 값과 동일해야 한다.

예시: "크림치즈와 설탕을 섞는" 단계라면
step_ingredients: [
  {"name": "크림치즈", "amount": 400, "unit": "g"},
  {"name": "설탕", "amount": 100, "unit": "g"}
]
```

**의도**: 조리 몰입 UI에서 사용자가 "현재 단계에서 필요한 재료가 무엇인지"를 한 화면에서 확인할 수 있도록, 각 단계에 필요한 재료를 미리 매핑해둡니다.

> 이 필드는 처음부터 설계된 것이 아니라, **조리 몰입형 UI/UX를 구현하는 과정에서 필요성을 발견하고 추가**했습니다. 전체 재료 목록을 다시 스크롤하지 않고 현재 단계의 재료만 보여주려면 데이터가 미리 매핑되어 있어야 했습니다. **UI 요구사항이 데이터 구조 설계로 이어진 사례**입니다.

또한 "이름은 반드시 전체 ingredients 목록에 존재하는 name 값과 동일해야 한다"는 제약을 추가해, 전체 재료 목록과 단계별 재료 사이의 참조 정합성을 보장했습니다. 이 제약이 없으면 LLM이 단계마다 재료 이름을 미세하게 다르게 표기해(예: "크림치즈" vs "크림 치즈") UI에서 매핑이 깨질 수 있습니다.

### 규칙 3. 계량 정보 정확성 — Hallucination 방지

```
재료의 계량(숫자, 단위)은 영상의 음성이나 자막에서 언급된 텍스트를
100% 최우선으로 따르며, 임의로 수치를 추정하거나 변경하지 마라.
```

**의도**: LLM이 가장 hallucination을 일으키기 쉬운 부분이 "원본에 없는 수치를 자체적으로 생성"하는 영역입니다. 예를 들어 영상에서 "두 큰술"이라고만 말했는데 LLM이 "30ml"로 변환해버리면 사용자가 잘못된 정보를 받게 됩니다.

레시피 서비스에서 계량 정보의 정확도는 결과물의 맛과 직결되는 핵심 요소이므로, **원본 표현을 그대로 유지하는 것을 최우선 원칙**으로 명시했습니다.

---

## 4. 응답 형식 — Structured Output

위 규칙들과 함께, LLM 응답은 **반드시 사전에 정의한 JSON 스키마에 맞춰 반환**되도록 강제했습니다.

```
결과는 반드시 정해진 JSON 스키마에 맞추어서 반환해라.
```

JSON 스키마 설계의 상세 의도와 검증 처리 방식은 [structured-output.md](./structured-output.md)에서 다룹니다.

---

## 5. 프롬프트 진화 과정과 한계 인지

> ⚠️ **솔직한 한계**: 본 프로젝트의 시스템 프롬프트는 생성형 AI(Google AI Studio, Gemini)와의 반복적인 대화를 통해 다듬어졌으나, **각 버전을 별도 파일로 기록해두지 않았습니다**. 따라서 이 섹션은 정확한 버전 히스토리가 아니라 "프롬프트가 어떤 의도의 변화를 거쳤는지에 대한 회고"입니다.

대략적인 변화 흐름:

1. **초기**: "레시피 영상에서 제목, 재료, 조리 단계를 추출해줘" 수준의 단순 지시
2. **중간**: 조리 단계 안에 재료 계량이 중복으로 들어가는 문제를 발견하고 규칙 1 추가
3. **현재**: 조리 몰입 UI 구현 과정에서 `step_ingredients`의 필요성을 발견하고 규칙 2 추가, hallucination 방지를 위한 규칙 3 명시, JSON 스키마 강제

## 6. 전체 시스템 프롬프트 (현재 버전)

전체 프롬프트는 `src/lib/recipe/extractPrompts.ts`에 정의되어 있습니다.

```typescript
export const SYSTEM_PROMPT = `너는 최고의 요리 전문가이자 레시피 구조화 AI야. 주어진 동영상이나 텍스트를 보고 오직 '요리 레시피'와 관련된 필수 정보(제목, 난이도, 몇인분, 재료, 스텝)만 정확하게 추출해야 해.

**[핵심 규칙 1: 조리 순서 텍스트 안에는 재료의 계량 수치(무게/부피) 금지, 단 시간과 온도는 무조건 보존]**
조리 순서(instruction) 텍스트 안에 절대 구체적인 재료 무게/부피 계량 수치(예: 370g, 200ml, 1큰술 등의 숫자+단위)를 적지 마라.
- BAD 예시: "크림치즈 370g을 볼에 넣고 부드럽게 풀어준다."
- GOOD 예시: "계량한 크림치즈를 볼에 넣고 부드럽게 풀어준다."
하지만 조리에 필요한 "시간(분, 시간, 초)"이나 "온도(도)"와 관련된 안내(예: "220도로 22분동안 구워주세요", "15분간 불려주세요")는 절대로 삭제하지 말고 원본 텍스트 그대로 보존해라.

**[핵심 규칙 2: 각 조리 단계별 사용되는 재료 안내(step_ingredients) 추출]**
각 조리 단계(step)마다 해당 단계에서 실제로 투입되거나 사용되는 재료들의 상세 정보(이름, 양, 단위)를 객체 배열 형식으로 명시해라.
이름은 반드시 전체 ingredients 목록에 존재하는 name 값과 동일해야 한다.
- 예시: "크림치즈와 설탕을 섞는" 단계라면 step_ingredients: [{"name": "크림치즈", "amount": 400, "unit": "g"}, {"name": "설탕", "amount": 100, "unit": "g"}]

**[핵심 규칙 3: 재료 계량 정확도]**
재료의 계량(숫자, 단위)은 영상의 음성이나 자막에서 언급된 텍스트를 100% 최우선으로 따르며, 임의로 수치를 추정하거나 변경하지 마라.

결과는 반드시 정해진 JSON 스키마에 맞추어서 반환해라.`;
```
